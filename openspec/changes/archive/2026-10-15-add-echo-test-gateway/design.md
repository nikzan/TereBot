# Design

## Context

ADR 0002 выносит весь Discord-I/O в Node-шлюз на `@discordjs/voice` 0.19.2. Состояние известных проблем на 2026-10-14:
- **#11419** (нулевой приём под DAVE) исправлен PR #11449, влит 2026-03-13 до выхода 0.19.2 (2026-03-17).
- **#11653 открыт, PR нет.** Если бот получает MLS welcome на transition 0 — то есть заходит в канал, где уже есть люди, — расшифровка потока участника не восстанавливается. Причина, по словам автора issue: `if (this.lastTransitionId)` в `DAVESession.decrypt` считает 0 ложным значением. У нас это **основной сценарий**: `/join` вызывает человек, который уже сидит в канале.
- **#11441** (до 34% потерь пакетов при смене ключей) закрыт как not planned. Эти потери мы принимаем и измеряем.

Каркас, настройки и логин бота даёт `setup-monorepo`.

## Goals / Non-Goals

**Goals:**
- Однозначно ответить, работает ли раздельный приём под DAVE достаточно надёжно для Клона.
- Сделать приёмник с интерфейсом, к которому на этапе 6 подключится WebSocket-мост в Python, а эхо и запись при этом не придётся менять.

**Non-Goals:**
- Качество звука сверх «как пришло из Discord»: никакого шумоподавления и нормализации.
- Протокол обмена с Python-ядром.

## Decisions

### Модули шлюза
```
connection.ts  подключение, переподключение, события DAVE → лог
receiver.ts    подписки по user ID, Opus → PCM, событие «кадр PCM {userId, pcm, t}»
watchdog.ts    правила переподписки и переподключения (чистая логика, часы подставляются)
mixer.ts       смешивание нескольких PCM-потоков в кадры по 20 мс
player.ts      AudioPlayer + Raw-ресурс, мгновенная остановка
echo.ts        подписчик receiver: задержка, затем mixer → player
recorder.ts    подписчик receiver: WAV и метаданные по участникам
commands.ts    /join, /leave, проверка whitelist, автовыход
```
`receiver.ts` — главный шов: эхо, запись и будущий WebSocket-мост подписываются на одни и те же кадры. Альтернатива «эхо прямо внутри приёмника» отвергнута, потому что на этапе 6 эхо пришлось бы вырезать.

### Декодирование
`receiver.subscribe(userId, { end: AfterSilence 1000 мс })` → `prism-media` Opus Decoder (48 кГц, 2 канала, кадр 960 сэмплов) → сведение в моно для записи. Для эха выход снова дублируется в стерео, потому что `StreamType.Raw` ожидает s16le 48 кГц стерео. Нативный `@discordjs/opus`; если на Apple Silicon он не соберётся, используем `opusscript` (медленнее, но это чистый JS).

### Обход #11653
Однострочный патч через `patch-package`: проверка `lastTransitionId !== undefined` вместо проверки на истинность. Патч лежит в `gateway/patches/` и применяется на `postinstall`. Патч надёжнее watchdog: watchdog лечит последствия, а патч устраняет причину. Watchdog всё равно нужен для других обрывов (#11441, сеть). При обновлении `@discordjs/voice` патч нужно пересмотреть; если upstream починит баг, патч удаляем.

### Watchdog
Срабатывает по двум сигналам:
1. Поток подписки закрылся с ошибкой расшифровки, а участник ещё говорит → немедленная переподписка.
2. Участник помечен говорящим (событие speaking start), а декодированных кадров от него нет дольше `watchdog_silence_ms` (3000) → переподписка.

После `watchdog_max_resubscribes` (3) неудачных переподписок за 60 с шлюз переподключается к тому же каналу. Логика написана как чистая функция «события + время → действие»: её можно тестировать на фиктивных часах без Discord. Какие события `@discordjs/voice` реально выдаёт при сбое расшифровки, проверяется отдельной задачей до реализации watchdog.

### Эхо и микшер
Для каждого участника есть очередь кадров с меткой времени получения. Таймер микшера каждые 20 мс берёт у каждого участника кадр, «созревший» на `echo_delay_ms`, суммирует их с насыщением до int16 и отдаёт в плеер. Если созревших кадров нет, плеер простаивает, а не играет тишину: иначе индикатор «говорит» у бота горит постоянно.

### Запись
Файл `data/recordings/<session-ts>/<user_id>.wav`: в заголовке сначала нулевые размеры, при закрытии они исправляются. Рядом `<user_id>.segments.jsonl`, по строке на фрагмент: `{start_ms, duration_ms, sample_offset}`. Тишина между фрагментами не пишется. Обработчики SIGINT и SIGTERM закрывают файлы до выхода.

### Регистрация команд
Slash-команды регистрируются на сервере из `guild_id`, а не глобально: так они появляются сразу, а глобальные — с задержкой до часа.

### Новые настройки
```toml
[gateway]
echo = true
echo_delay_ms = 2000
autoleave_s = 30
watchdog_silence_ms = 3000
watchdog_max_resubscribes = 3

[recording]
enabled = true
dir = "data/recordings"
```

## Risks / Trade-offs

- [Патч к #11653 неверен или недостаточен] → Эхо-тест обязательно включает сценарий «бот зашёл к людям», а watchdog страхует. Если не помогает ни то, ни другое, переходим к плану (б) из ADR 0002.
- [Потери пакетов при смене ключей (#11441) режут фразы] → в Эхо-тесте мерим долю потерь по логу. Для диалога короткие провалы допустимы, для датасета такие фрагменты отсеются на этапе 4.
- [`@discordjs/opus` не собирается на arm64] → запасной `opusscript`.
- [Таймер микшера на 20 мс в JS неточен] → допустимо для эха: это тестовый режим, а не продакшен-воспроизведение Голоса.
