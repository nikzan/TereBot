# Spec Delta

## Purpose

Определяет, откуда Клон берёт секреты и настройки (бот-токен, сервер, whitelist участников), как проверяет их при старте и как гарантирует, что секреты и личные данные не попадут в репозиторий.

## ADDED Requirements

### Requirement: Секреты только в .env
Бот-токен и прочие секреты Клон SHALL читать только из переменных окружения или файла `.env` в корне репозитория. Сам `.env` MUST быть исключён из git, а в репозитории MUST лежать `.env.example` с теми же ключами, но без значений.

#### Scenario: Токен задан в .env
- **WHEN** в `.env` указан `DISCORD_TOKEN`, и шлюз запущен
- **THEN** шлюз авторизуется в Discord с этим токеном

#### Scenario: .env не попадает в git
- **WHEN** владелец выполняет `git status` при заполненном `.env`
- **THEN** `.env` не отображается среди неотслеживаемых файлов

### Requirement: Отказ при отсутствии токена
Если токен не задан, Клон SHALL завершиться с ненулевым кодом выхода и понятным сообщением, какую переменную нужно задать. Значение токена Клон MUST NOT выводить в лог.

#### Scenario: Токена нет
- **WHEN** шлюз запущен без `DISCORD_TOKEN`
- **THEN** процесс завершается с ненулевым кодом, а сообщение называет переменную `DISCORD_TOKEN` и файл `.env.example`

#### Scenario: Ошибки не раскрывают токен
- **WHEN** Discord отклоняет токен как неверный
- **THEN** в сообщении об ошибке нет значения токена

### Requirement: Общий файл настроек
Несекретные настройки — ID сервера и список Discord user ID из whitelist — Клон SHALL читать из одного файла: `config/settings.local.toml`, если он существует, иначе `config/settings.toml`. Выбор файла MUST быть одинаковым для Node-шлюза и Python-ядра. `config/settings.toml` лежит в git с плейсхолдерами, а `config/settings.local.toml` с реальными ID MUST быть исключён из git. Файлы не сливаются: локальный заменяет общий целиком.

#### Scenario: Шлюз и ядро видят одинаковые настройки
- **WHEN** в файле настроек указан whitelist из трёх user ID
- **THEN** и шлюз, и ядро после загрузки настроек получают одни и те же три ID

#### Scenario: Локальный файл заменяет общий
- **WHEN** рядом с `config/settings.toml` лежит `config/settings.local.toml`
- **THEN** шлюз и ядро читают только `config/settings.local.toml`, а поля, которых в нём нет, из `config/settings.toml` не берутся

#### Scenario: Реальные ID не попадают в git
- **WHEN** владелец вписал реальные ID в `config/settings.local.toml` и выполняет `git status`
- **THEN** `config/settings.local.toml` не отображается среди неотслеживаемых файлов

### Requirement: Проверка настроек при старте
Клон SHALL проверять настройки при старте. Если обязательного поля нет или у него неверный тип, Клон MUST завершиться с сообщением, где указаны имя поля и прочитанный файл.

#### Scenario: Пустой whitelist
- **WHEN** в `config/settings.toml` нет ни одного user ID в whitelist
- **THEN** старт прерывается с сообщением, что whitelist пуст

### Requirement: Личные данные вне git
Каталог `data/`, где лежат голос Прототипа, записи участников и Журналы Сессий, MUST быть исключён из git.

#### Scenario: Файл в data/
- **WHEN** в `data/` появляется WAV-файл
- **THEN** `git status` его не показывает

### Requirement: Бот онлайн на тестовом сервере
Шлюз SHALL с корректным токеном и настройками авторизоваться в Discord и записать в лог, что бот онлайн и находится на сервере из настроек. Если бот на этот сервер не приглашён, шлюз MUST сообщить об этом в лог.

#### Scenario: Успешный вход
- **WHEN** шлюз запущен с корректными `.env` и `config/settings.toml`, а бот приглашён на тестовый сервер
- **THEN** в логе есть имя бота и название тестового сервера, а в Discord бот отображается онлайн

#### Scenario: Бот не на сервере
- **WHEN** ID сервера в настройках указывает на сервер, куда бот не приглашён
- **THEN** шлюз пишет в лог предупреждение со ссылкой на инструкцию по приглашению бота
