# Proposal

## Why

Реализует **этап 4 «Сбор данных»** из `docs/PLAN.md`. Узнаваемость Голоса — главный приоритет, а главный рычаг похожести — 30–60 минут чистой разговорной речи Прототипа с точными транскриптами. Ошибки в транскриптах — основная причина «каши» после дообучения. Пока данных нет совсем.

Записывать отдельно не нужно: на Эхо-тесте шлюз уже показал, что пишет поток каждого участника из whitelist в отдельный WAV, не сохраняет тишину и кладёт рядом границы фрагментов речи. Если оставить в whitelist только Прототипа и выключить эхо, обычная Сессия в Discord станет сессией записи. Не хватает двух вещей: короткого чек-листа, чтобы клиент Discord не портил тембр, и конвейера, который превращает записи шлюза в проверенный датасет. Конвейер строится независимо от выбора модели Голоса: приводить данные к формату конкретной модели будет этап 5.

## What Changes

- Чек-лист сессии записи: наушники у Прототипа, отключённые шумоподавление, эхоподавление и автоусиление в клиенте Discord, битрейт голосового канала 96 кбит/с, настройки шлюза (`echo = false`, в whitelist только Прототип), темы для свободного разговора, количество и длительность Сессий.
- Чтение записей шлюза: конвейер берёт из `data/recordings/<Сессия>/` WAV Прототипа и его `segments.jsonl` напрямую, без отдельного импорта.
- Нормализация громкости к единому уровню. Формат приводить не нужно: шлюз уже пишет моно 48 кГц.
- Нарезка на сегменты по 3–15 с: границы фрагментов шлюза жёсткие, длинные фрагменты делятся по паузам, без обрыва слов, с отбраковкой слишком тихих, клиппированных и слишком коротких.
- Автоматическая транскрипция сегментов.
- Ручная вычитка: инструмент в терминале — прослушать сегмент, принять, исправить текст или отбраковать — с сохранением прогресса.
- Манифест JSONL из принятых сегментов с отложенной тестовой выборкой без утечки между выборками, плюс отчёт со статистикой (минуты по Сессиям, распределение длительностей).

**Вне рамок:** локальная запись у Прототипа (WAV 24 бит в Audacity и аналогах) и её импорт. Шумоподавление в конвейере. Изменения кода шлюза. Приведение к формату обучения конкретной модели и само дообучение (этап 5). Диаризация и фильтр «чужого» голоса по эмбеддингу: раздельные потоки и наушники по чек-листу делают их ненужными. Экспорт текстовой переписки для Паспорта.

## Impact

- Код: `scripts/dataset/` (segment, transcribe, review, build), `src/terebot/dataset/`. Код шлюза не меняется.
- Настройки: на время сбора в `config/settings.local.toml` стоят `echo = false` и whitelist из одного Прототипа.
- Документы: `docs/recording-checklist.md`, `docs/transcription-guide.md`; в `docs/PLAN.md` записи шлюза становятся единственным источником.
- Зависимости (группа `data`): `silero-vad`, `onnx-asr`, `soundfile`, `pyloudnorm`.
- Данные: читаются из `data/recordings/`, результат — в `data/dataset/` (вне git; на кластер переносится через rsync).
- Опирается на capability `voice-recording` (формат WAV и `segments.jsonl`) из `add-echo-test-gateway`.
