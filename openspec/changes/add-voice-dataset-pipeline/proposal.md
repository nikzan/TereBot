# Proposal

## Why

Реализует **этап 4 «Сбор данных»** из `docs/PLAN.md`. Узнаваемость Голоса — главный приоритет, а главный рычаг похожести — 30–60 минут чистой разговорной речи Прототипа с точными транскриптами. Ошибки в транскриптах — основная причина «каши» после дообучения. Пока данных нет совсем, поэтому нужны и протокол записи, и конвейер, который превращает сырые записи в проверенный датасет. Конвейер строится независимо от выбора модели Голоса: модель станет известна на этапе 3, а приводить данные к формату конкретной модели будет этап 5.

## What Changes

- Протокол записи для владельца и Прототипа: оборудование, настройки (WAV 48 кГц / 24 бит, моно), обязательные наушники, темы для свободного разговора, количество и длительность сессий.
- Импорт источников: локальные записи Прототипа (основной источник) и раздельные потоки из Discord-шлюза (запасной). У каждого источника сохраняется происхождение.
- Подготовка аудио: моно, единая частота, нормализация громкости. Лёгкое шумоподавление только по флагу.
- Нарезка на сегменты по 3–15 с по паузам, без обрыва слов, с отбраковкой слишком тихих, клиппированных и слишком коротких фрагментов.
- Автоматическая транскрипция сегментов.
- Ручная вычитка: инструмент в терминале — прослушать сегмент, принять, исправить текст или отбраковать — с сохранением прогресса.
- Манифест JSONL из принятых сегментов с отложенной тестовой выборкой без утечки между выборками, плюс отчёт со статистикой (минуты по источникам, распределение длительностей).

**Вне рамок:** приведение к формату обучения конкретной модели и само дообучение (этап 5). Диаризация и фильтр «чужого» голоса по эмбеддингу: их заменяет требование наушников в протоколе. Разделение голоса и музыки (её не должно быть по протоколу). Экспорт текстовой переписки для Паспорта.
