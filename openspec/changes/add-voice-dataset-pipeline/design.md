# Design

## Context

Данных Прототипа нет. По решению из PLAN.md основной источник — удалённые сессии, где каждый пишет себя локально, а Discord нужен только для связи. Запасной источник — WAV и `segments.jsonl` из `add-echo-test-gateway` (48 кГц, 16 бит, моно, Opus-качество). Модель Голоса выбирается на этапе 3, поэтому датасет хранится в нейтральном формате, а конвертацию под модель делает этап 5. Конвейер работает на Mac на CPU.

## Goals / Non-Goals

**Goals:**
- Прозрачный конвейер из шагов-скриптов. Каждый шаг идемпотентен и перезапускается без потери ручной работы.
- Минимум трения при вычитке: это 2–4 часа ручной работы и лучшее вложение времени в проекте.

**Non-Goals:**
- Фильтр чужого голоса по эмбеддингу спикера: его заменяют наушники по протоколу. Если в записях всё же окажется голос владельца, фильтр добавим отдельным изменением, переиспользовав `voice-quality-metrics`.
- Веб-интерфейс вычитки.

## Decisions

### Шаги и каталоги
```
scripts/dataset/import.py      → data/raw/<session>/<file>.wav + source.json
scripts/dataset/prepare.py     → data/dataset/prepared/<session>/<file>.wav
scripts/dataset/segment.py     → data/dataset/segments/<seg_id>.wav + segments.jsonl
scripts/dataset/transcribe.py  → дописывает auto_text в review.jsonl
scripts/dataset/review.py      → правит text/status в review.jsonl
scripts/dataset/build.py       → data/dataset/manifest/{train,holdout}.jsonl + report.md
```
Каждый шаг пропускает уже обработанное. `review.jsonl` — единственный файл с ручным трудом. Повторные `segment` и `transcribe` MUST NOT перезаписывать в нём `text` и `status`, если `seg_id` не изменился. `seg_id` детерминированно строится из исходного файла и времени начала, поэтому совпадает при повторной нарезке с теми же параметрами.

### Подготовка
`soundfile` + `soxr` для ресемплинга (качество VHQ), `pyloudnorm` для нормализации к −23 LUFS. Без лимитера: клиппинг отбраковывается, а не маскируется. DeepFilterNet — только по флагу `--denoise`, слабым уровнем: сильное шумоподавление «съедает» тембр.

### Нарезка
Silero VAD с порогами для разговорной речи. Склеиваем речевые отрезки с паузами короче 0,3 с, пока сегмент не превысит 15 с, и режем по самой длинной паузе внутри. По краям добавляем отступ 100–150 мс, чтобы не резать согласные. Отбраковываем сегменты короче 3 с, с клиппингом (доля сэмплов ≥ 0,99 FS выше порога) и слишком тихие. Причина отбраковки пишется в `segments.jsonl`.

### Транскрипция
`onnx-asr` с `gigaam-v3-e2e-rnnt`: офлайн качество важнее скорости, а RNNT точнее CTC. Модель e2e расставляет пунктуацию и регистр, и это сокращает правки при вычитке.

### Вычитка
Терминальный цикл: воспроизведение через `afplay`, затем показ `auto_text` или уже исправленного `text`, затем клавиши: Enter — принять, `e` — открыть текст в `$EDITOR` или во встроенном однострочном редакторе, `r` — отбраковать с причиной, `p` — прослушать ещё раз, `q` — выйти. После каждого решения `review.jsonl` атомарно перезаписывается (через временный файл и rename). Свой TUI-фреймворк не используем: хватит `input()` и ANSI-цветов.

### Манифест
Строка манифеста: `{"audio": "segments/<id>.wav", "text": "...", "duration": 7.4, "source": "local|discord", "session": "...", "seg_id": "..."}`. Пути относительные к `data/dataset/`, поэтому датасет переносится на кластер через rsync без правок.

Отложенная выборка: сегменты группируются в блоки по исходному файлу и окнам по 2 минуты. Блоки сортируются по хешу `session + номер окна`, и отбираются первые, пока не наберётся ~10% длительности. Так разбиение детерминированно и не делит соседние сегменты между выборками.

## Risks / Trade-offs

- [Порог 3 с отбрасывает короткие характерные реакции («ага», «да ну»)] → порог — параметр. Влияние на Голос оценим на этапе 5 и при необходимости снизим.
- [Голос владельца просачивается в дорожку Прототипа, если наушников нет] → протокол требует наушники, а вычитка отбраковывает такие сегменты. Если их много, добавляем фильтр по эмбеддингу (см. Non-Goals).
- [Записи из Discord хуже по тембру (Opus, шумодав клиента)] → источник помечен в манифесте, и на этапе 5 их можно исключить или ограничить их долю.
- [Терминальное воспроизведение через `afplay` есть только на macOS] → вычитка делается на Mac владельца, этого достаточно.
