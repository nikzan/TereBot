# Design

## Context

Факты на 2026-10-14 (см. `docs/REFERENCES.md`):
- Официальный `qwen-tts` 0.1.1: примеры только на CUDA, о MPS ничего. Issue #237 сообщает о закреплённой `transformers==4.57.3`; это нужно проверить.
- Сторонний замер Qwen3-TTS-1.7B через PyTorch MPS на M3 Max: RTF 2,5–3,5 (https://tinycomputers.io/posts/the-real-cost-of-running-qwen-tts-locally-three-machines-compared.html). M1 Pro заметно слабее M3 Max.
- `mlx-audio` 0.5.9 поддерживает Qwen3-TTS со стримингом. Готовые конвертации есть в `mlx-community/Qwen3-TTS-12Hz-{1.7B,0.6B}-Base-{bf16,8bit,4bit}`. Сторонний замер на M5 Pro через MLX: RTF 0,79–0,85 (https://soniqo.audio/benchmarks).
- Бюджет памяти из `docs/PLAN.md`: Голос ~5 ГБ, LLM ~3 ГБ, распознавание ~1 ГБ на 16 ГБ.

Референс для zero-shot — 10–15 с голоса владельца с транскриптом, потому что записей Прототипа пока нет. Похожесть считается относительно других записей владельца.

## Goals / Non-Goals

**Goals:**
- Получить на M1 Pro фактические RTF, время до первого звука и память для каждой разумной конфигурации и выбрать одну.
- Проверить путь «чекпоинт PyTorch → MLX»: от него зависит, сможем ли мы запускать на MLX Голос, дообученный на CUDA-кластере.

**Non-Goals:**
- Оптимизация конкретной конфигурации сверх параметров библиотеки (свои ядра, компиляция).
- Окончательный выбор по качеству голоса Прототипа: здесь выбираем по скорости, а качество zero-shot оцениваем только грубо.

## Decisions

### Матрица конфигураций (в порядке прогона)
| # | Модель | Бэкенд | Точность |
|---|---|---|---|
| 1 | Qwen3-TTS-12Hz-1.7B-Base | PyTorch MPS | bf16 |
| 2 | Qwen3-TTS-12Hz-1.7B-Base | MLX | bf16 |
| 3 | Qwen3-TTS-12Hz-1.7B-Base | MLX | 8-bit |
| 4 | Qwen3-TTS-12Hz-0.6B-Base | MLX | bf16 |
| 5 | Qwen3-TTS-12Hz-0.6B-Base | PyTorch MPS | bf16 |
| 6 | Chatterbox Multilingual | PyTorch MPS (или MLX, если поддерживается) | по умолчанию |

MLX — не новый пункт запасного плана, а другой рантайм той же основной модели, поэтому идёт сразу после MPS. Порядок запасных моделей из PLAN.md (0.6B → Chatterbox → без стриминга) сохраняется. 4-bit не берём: синтез речи чувствителен к квантизации. 4-bit проверим, только если 8-bit не уложится в память. Если конфигурация 2 или 3 проходит условие, остальные всё равно прогоняются (кроме 6, если Qwen уже прошёл), чтобы в отчёте был запас для выбора.

### Изоляция зависимостей
`qwen-tts` закрепляет `transformers`, у `chatterbox-tts` и `mlx-audio` свои требования. Делаем три группы зависимостей uv: `tts-qwen-torch`, `tts-mlx`, `tts-chatterbox`. Они объявлены взаимоисключающими через `[tool.uv] conflicts`, и каждая конфигурация запускается как `uv run --group <g>`. Отдельные виртуальные окружения вне uv отвергнуты: потерялась бы воспроизводимость через `uv.lock`.

### Структура кода
- `scripts/bench_voice.py --config <id> [--with-llm]` — прогон одной конфигурации, пишет `data/bench/<ts>-<id>/` (WAV и `results.json`).
- `src/terebot/voice_eval/` — метрики похожести и CER. Этот модуль переиспользуется на этапе 5.
- Адаптер для каждого бэкенда реализует один интерфейс: `load(model, precision)`, `prepare_voice(ref_wav, ref_text)`, `synthesize(text) -> итератор чанков`. Подготовка промпта голоса (`create_voice_clone_prompt` у qwen-tts) выполняется один раз и в замер не входит.

### Замеры
- Время синтеза — по `time.perf_counter`. Первый чанк — момент, когда итератор выдал первый аудиобуфер.
- Память: MLX — `mx.get_peak_memory()`, MPS — `torch.mps.driver_allocated_memory()`, плюс пиковый RSS процесса через `psutil`. В режиме `--with-llm` дополнительно суммарная используемая память системы (`vm_stat`).
- Прогрев: 3 фразы вне набора.

### Метрики качества
- Похожесть: эмбеддинги ECAPA-TDNN из SpeechBrain (`speechbrain/spkrec-ecapa-voxceleb`). WavLM-SV отвергнут: тяжелее, а для сравнения конфигураций между собой достаточно ECAPA.
- CER: `onnx-asr` с `gigaam-v3-e2e-ctc` — то же распознавание, что будет в Клоне.

### Режим с LLM
Перед прогоном вручную запускается `llama-server` с Qwen3.5-4B Q4_K_M (`unsloth/Qwen3.5-4B-GGUF`), и в него отправляется один запрос, чтобы веса реально легли в память. Бенчмарк проверяет, что сервер отвечает на `/health`, и записывает его PID и модель в результаты.

### Проверка пути PyTorch → MLX
Конвертируем официальный `Qwen/Qwen3-TTS-12Hz-1.7B-Base` в MLX штатным конвертером `mlx-audio` и сравниваем с готовой конвертацией из `mlx-community` на одних и тех же фразах и сиде. Если конвертации не получилось или звучание заметно отличается, MLX-путь для дообученного Голоса под вопросом, и это фиксируется в отчёте.

## Risks / Trade-offs

- [Ни одна конфигурация не даёт RTF < 1 вместе с LLM] → отчёт фиксирует провал условия, и дальше идём по запасному плану PLAN.md до «синтеза фразы целиком без стриминга». Решение пересматриваем с владельцем.
- [Сторонние MLX-конвертации отличаются от оригинала] → проверка пути PyTorch → MLX собственной конвертацией.
- [На MPS не хватает операторов] → запуск с `PYTORCH_ENABLE_MPS_FALLBACK=1`; часть вычислений на CPU фиксируется в отчёте как причина медленности.
- [Похожесть на голосе владельца не предсказывает похожесть на Прототипе] → на этом этапе метрика только отсеивает явно плохие конфигурации, а финальная оценка будет на этапе 5.
- [Swap на 16 ГБ искажает замеры] → в режиме с LLM дополнительно записывается использование swap. Если swap растёт, конфигурация считается не уложившейся в память.
