# Design

## Context

В репозитории есть только документация, `.gitignore` и `pyproject.toml`, сгенерированный uv (Python 3.12). Окружение: Node v22.23 и uv. По ADR 0002 с Discord работает только Node-шлюз, поэтому бот-токен нужен только ему, а Python-ядру достаточно несекретных настроек.

## Goals / Non-Goals

**Goals:**
- Зафиксировать раскладку монорепо и инструменты так, чтобы следующие изменения только добавляли код.
- Проверить, что Discord-приложение настроено правильно: бот онлайн.

**Non-Goals:**
- Сборка и публикация, CI, Docker: Клон запускается локально вручную.
- Общий для Node и Python менеджер процессов: появится, когда будет что запускать вместе (этап 6).

## Decisions

### Раскладка
```
gateway/            Node-шлюз (TypeScript, без шага сборки)
src/terebot/        Python-ядро (uv, src-layout)
tests/              pytest
config/settings.toml  несекретные настройки (в git)
scripts/            подготовка данных, бенчмарки, обучение
data/               в .gitignore
.env / .env.example секреты
```

### TypeScript без сборки
Пишем шлюз на TypeScript и запускаем его напрямую через `node`: в Node 22.18+ type stripping включён по умолчанию. Вариант с обычным JS отвергнут: в шлюзе много событийных структур (SSRC, user ID, кадры), и типы ловят путаницу. Вариант `tsc` со сборкой отвергнут как лишний шаг. Если для тестов понадобится поддержка TS-синтаксиса, которого нет в type stripping (например, enum), такой синтаксис не используем.

### .env грузит сам Node
Используем `node --env-file-if-exists=../.env`: никаких зависимостей вроде dotenv. Вариант `--env-file` не подходит: без `.env` Node падает раньше, чем шлюз успевает подсказать про `.env.example`. Python-ядру токен не нужен, поэтому `.env` оно не читает.

### Настройки в TOML
`config/settings.toml` читается в Python через `tomllib` (стандартная библиотека), а в Node через `smol-toml`. JSON отвергнут: в нём нельзя оставлять комментарии к порогам, которых позже станет много. YAML отвергнут из-за неоднозначностей типов. Проверку схемы пишем в каждом языке вручную, на несколько полей. Валидатор схемы, общий для двух языков, не делаем: пока полей мало, он не окупится.

Начальная схема:
```toml
[discord]
guild_id = "..."          # тестовый сервер
whitelist = ["...", "..."]  # Discord user ID
```

### Права Discord-приложения
- Scopes: `bot`, `applications.commands`.
- Права бота: View Channel, Connect, Speak.
- Gateway intents: `Guilds`, `GuildVoiceStates`. Message Content не нужен: Клон работает только с голосом и slash-командами.

### Python-инструменты
`ruff` для линтинга и форматирования и `pytest` — в группе `dev`. Группа `train` создаётся пустой, чтобы зафиксировать соглашение из PLAN.md. Python 3.12: его рекомендует Qwen3-TTS.

## Risks / Trade-offs

- [Type stripping не поддерживает часть TS-синтаксиса (enum, namespace, parameter properties)] → пишем в подмножестве «типы поверх JS»; при необходимости позже подключим `tsx`.
- [Ручная проверка настроек в двух языках может разойтись] → у обоих одна схема, и тест загружает один и тот же `config/settings.toml` (сценарий «Шлюз и ядро видят одинаковые настройки»).
