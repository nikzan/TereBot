# Сценарии Политики Диалога

Каждый файл `scenarios/*.yaml` — один случай из жизни канала: что происходит по времени и что
Клон должен решить. Чтобы добавить случай, скопируйте похожий файл, поменяйте шаги и запустите:

```bash
uv run pytest tests/dialogue
```

Один сценарий: `uv run pytest tests/dialogue -k <имя файла без .yaml>`.

## Пример

```yaml
# Переключение на нового вызвавшего → Вызов, пока Клон говорит
name: Вася перехватывает, пока Клон говорит
whitelist: [petya, vasya]
steps:
  - {t: 0.0, utterance: {user: petya, text: "Теребот, расскажи про отпуск"}}
  - expect: [StartDialogue(petya), Respond]
  - {t: 1.0, clone: started}
  - {t: 2.5, utterance: {user: vasya, text: "Теребот, а мне ответь"}}
  - expect: [StopAfterCurrentPhrase, SwitchInterlocutor(vasya)]
  - {t: 3.1, clone: phrase_ended}
  - expect:
      - Respond: {texts: ["Теребот, а мне ответь"]}
```

## Поля файла

- `name` — название случая человеческими словами.
- `whitelist` — участники, которых Клон слушает. Имена любые (`petya`, `vasya`); кто не в списке —
  гость, которого Клон не слышит вовсе.
- `settings` (необязательно) — заменить настройки `[dialogue]` из `config/settings.toml` только для
  этого случая, например `settings: {wake_words: ["тереша"], window_s: 10}`. Без этого поля —
  значения по умолчанию.
- `steps` — шаги по порядку. Время `t` — секунды от начала, не убывает.

## Шаги-события

| Шаг | Что значит |
|---|---|
| `{t: 5, utterance: {user: petya, text: "…"}}` | Петя договорил Реплику, распознавание выдало текст. `t` — конец Реплики. Можно добавить `start: 3` — когда Петя начал говорить (по умолчанию = `t`) |
| `{t: 5, speech: {user: petya, ms: 1200}}` | Петя говорит прямо сейчас, уже 1200 мс подряд (Реплика ещё не готова). Так проверяется перебивание и то, что Собеседник не молчит |
| `{t: 5, clone: started}` | Клон начал говорить подготовленный ответ |
| `{t: 5, clone: phrase_ended}` | Клон договорил очередную фразу ответа |
| `{t: 5, clone: finished}` | Клон договорил ответ целиком |
| `{t: 5, clone: failed}` | Ответ не удалось подготовить (сбой LLM или Голоса) |
| `{t: 5, left: petya}` | Петя вышел из голосового канала |
| `{t: 25, tick: true}` | Просто прошло время до `t`: так проверяется окно ожидания |

В одном шаге — одно событие.

## Шаг `expect` — какие решения ожидаются

`expect` перечисляет **все** решения Политики, принятые с предыдущего `expect`, по порядку. Если
решений не должно быть — `expect: []`. Решения, которые остались непроверенными к концу файла,
тоже считаются ошибкой.

| Решение | Значит |
|---|---|
| `StartDialogue` | начать Диалог; `StartDialogue(petya)` — с Петей |
| `Respond` | подготовить ответ Собеседнику |
| `AddToContext` | учесть Реплику, не отвечая; `AddToContext(vasya)` — Реплику Васи |
| `InterruptClone` | Клон замолкает сразу |
| `StopAfterCurrentPhrase` | Клон договаривает звучащую фразу, остальное не произносит |
| `CancelPendingResponse` | бросить ответ, который ещё готовится и не начал звучать |
| `SwitchInterlocutor` | сменить Собеседника; `SwitchInterlocutor(vasya)` — на Васю |
| `EndDialogue` | закончить Диалог |

Если нужно проверить подробнее, решение пишется так: `{Имя: {поле: значение}}`.

- `user` — чей это вызов или Реплика.
- `text` — кусок текста Реплики (для `StartDialogue` и `AddToContext`).
- `texts` — точный список Реплик, на которые отвечает `Respond`, например
  `Respond: {texts: ["Теребот, как думаешь", "стоит купить видеокарту?"]}`.
- `reason` — кусок причины, которую Политика пишет в Журнал Сессии, например
  `StartDialogue: {reason: "найдено Слово-вызов"}`.

## Шаг `state` — что сейчас в Политике

`- state: {dialogue: true, interlocutor: petya, clone: idle, window_left: 4.0}` — проверить только
перечисленные поля:

- `dialogue` — идёт ли Диалог (`true`/`false`);
- `interlocutor` — кто Собеседник (`null`, если Диалога нет);
- `clone` — `idle` (молчит), `preparing` (готовит ответ), `speaking` (говорит);
- `stopping` — Клон договаривает фразу, чтобы ответить новому Собеседнику;
- `window_left` — сколько секунд осталось до конца окна ожидания на момент последнего шага
  (`null`, пока окно не идёт: Клон говорит или готовит ответ, или Диалога нет).

## Как читать ошибку

```
02_switch.yaml, шаг 5 (t=2.5): решения не совпали
  ожидалось:
    - StopAfterCurrentPhrase
    - SwitchInterlocutor(user='vasya')
  получено:
    - AddToContext(vasya, 'Теребот, а мне ответь') — Реплика не Собеседника без Слова-вызова
```

Слева номер шага и время, ниже — что ждали и что Политика решила на самом деле с причиной.
Если случай верный, а Политика ошибается, — это повод поправить Политику, а не сценарий.

## Как устроены настоящие события

- Слово-вызов видно только в готовой Реплике, поэтому переключение и начало Диалога происходят
  на шаге `utterance`, а не раньше.
- Окно ожидания отсчитывается от конца ответа Клона и от последней речи Собеседника (`utterance` или
  `speech`). Если Собеседник говорит долго, добавляйте шаги `speech` каждые несколько секунд, как
  это делает распознавание речи в канале.
- Первая строка-комментарий в файле называет требование и сценарий из спецификации
  `openspec/specs/dialogue-policy/spec.md` (до архивации change — в
  `openspec/changes/add-dialogue-policy/specs/`), которые файл проверяет. Свои случаи помечайте
  `# Свой случай`.
