# Discord-шлюз Клона

Node-шлюз из ADR 0002: весь Discord-I/O Клона. Сейчас — этап 2 «Эхо-тест»: `/join` и `/leave`, раздельный приём голоса участников под DAVE, режим эха и запись WAV по участникам.

```bash
cd gateway
npm ci          # на postinstall применяется патч из patches/ (обход #11653)
npm test
npm start       # токен из ../.env, настройки из ../config/
```

Модули `src/`:

| Файл | Что делает |
|---|---|
| `connection.ts` | Подключение к каналу, переподключение, лог состояний и событий DAVE |
| `receiver.ts` | Подписки по user ID, Opus → PCM, события `segmentStart` / `frame` / `segmentEnd`, счётчики пакетов |
| `watchdog.ts` | Правила переподписки и переподключения (чистая логика) |
| `mixer.ts`, `player.ts`, `echo.ts` | Режим эха: задержка, смешивание, воспроизведение |
| `recorder.ts` | WAV и `segments.jsonl` по участникам из whitelist |
| `commands.ts` | `/join`, `/leave`, whitelist, автовыход |

Настройки — секции `[gateway]` и `[recording]` в `config/settings.toml`. Обе необязательны: если в `config/settings.local.toml` их нет, действуют значения по умолчанию из `config/settings.toml`.

## Строки лога

Формат: `<время ISO> [<тег>] <сообщение>`. Теги:

- `[voice]` — состояния соединения (`состояние signalling → connecting`), подключения, отключения, переподключения.
- `[dave]` — debug-сообщения сессии DAVE из `@discordjs/voice` и `transitioned id=N`.
- `[recv]` — подписки, ошибки потоков и декодирования, решения watchdog.
- `[stats]` — раз в минуту и в конце Сессии: накопленные счётчики по каждому участнику.
- `[player]`, `[commands]`, `[gateway]` — остальное.

Строка `[stats]`:

```
2026-10-15T18:01:00.000Z [stats] user=111111111111111111 rtp=2950 seq_lost=12 dave_dropped=40 decoded=2908 decode_err=2 stream_err=0 resub=0 lost=1.8%
```

| Поле | Значение |
|---|---|
| `rtp` | RTP-пакеты Opus от участника, пришедшие по UDP, пока на него была подписка |
| `seq_lost` | Пропуски в номерах RTP: пакеты, потерянные по дороге |
| `dave_dropped` | Пакеты, которые пришли, но не дошли до потока подписки (DAVE не расшифровал, `rtp − pushed`) |
| `decoded` | Кадры 20 мс, которые декодировал Opus |
| `decode_err`, `stream_err`, `resub` | Ошибки Opus, падения потока подписки, переподписки watchdog |
| `lost` | `(rtp + seq_lost − decoded) / (rtp + seq_lost)`: доля потерянного звука участника |

## Сбои приёма в @discordjs/voice 0.19.2

Разбор по коду `dist/index.mjs`, проверенный прогоном 2026-10-14 (вы и гость, ~14 минут, лог `data/precheck.log`). Примеры строк — из этого лога, user ID заменены.

Что происходит с пакетом участника (`VoiceReceiver.onUdpMessage`):

1. Любой RTP-пакет с известным SSRC вызывает `speaking.onPacket(userId)`. Это происходит **до** расшифровки, поэтому событие `speaking start` приходит и тогда, когда DAVE пакеты не расшифровывает. На этом и построено правило watchdog «говорит, но кадров нет».
2. Если подписки на участника нет, пакет отбрасывается молча.
3. Транспортная расшифровка (aes-256-gcm). При ошибке бросается `Failed to parse packet`, поток подписки уничтожается с этой ошибкой: событие `error` у `AudioReceiveStream`, затем `close`. В лог: `[recv] user=… поток подписки упал: Failed to parse packet`.
4. Расшифровка DAVE (`DAVESession.decrypt`):
   - Сессия не готова или участник в режиме passthrough — пакет проходит **как есть**. Если он на самом деле зашифрован, Opus его не декодирует: растёт `decode_err`, в лог `[recv] … ошибка декодирования Opus`.
   - Ошибка расшифровки — пакет отбрасывается (`null`, растёт `dave_dropped`), в лог `[dave] Failed to decrypt a packet (N consecutive fails)`. Во время перехода — `(N pending transition[s])`, при переинициализации — `(reinitializing session)`. Эти два варианта в счётчик подряд идущих ошибок не идут.
   - Больше 36 ошибок подряд (`decryptionFailureTolerance`) — `recoverFromInvalidTransition(lastTransitionId)`: в лог `[dave] Invalidating transition N`, сессия пересоздаётся. Без патча при `lastTransitionId === 0` (бот зашёл к людям, #11653) вместо этого ошибка пробрасывалась и уничтожала поток подписки. С патчем идёт восстановление.
5. Потеря пакетов в сети ничего не выдаёт: поток просто молчит. Её видно только по номерам RTP (`seq_lost`). Потери при смене ключей (#11441) видны как всплеск `dave_dropped` рядом со строками `[dave] Preparing for transition` / `Transition executed`.
6. Поток подписки закрывается сам через 1 с без пакетов (`EndBehaviorType.AfterSilence`). Это нормальный конец фрагмента, а не сбой.

### Что показал прогон

Ни разу не было `Invalidating transition`, `stream_err`, `decode_err` или переподписки watchdog. Все ошибки расшифровки DAVE — короткие серии, которые проходят сами.

**Бот заходит к людям.** Welcome на transition 1, затем несколько ошибок подряд, и приём идёт:

```
21:20:42.791Z [dave] Session initialized for protocol version 1
21:20:42.800Z [voice] состояние connecting → ready
21:20:43.009Z [dave] MLS welcome processed (transition id: 1)
21:20:43.135Z [dave] Transition executed (v1 -> v1, id: 1)
21:20:43.183Z [dave] Failed to decrypt a packet (1 consecutive fails)
…
21:20:43.283Z [dave] Failed to decrypt a packet (6 consecutive fails)
```

**Участник выходит или заходит (ротация ключей).** Commit и переход, потом всплеск ошибок у того, кто говорит. Самая длинная серия — 14 подряд, это меньше порога 36. У участника за минуту `dave_dropped` вырос на 35 (~0,7 с звука):

```
21:25:50.179Z [dave] MLS commit processed (transition id: 3)
21:25:50.336Z [dave] Transition executed (v1 -> v1, id: 3)
21:25:50.434Z [dave] Failed to decrypt a packet (1 consecutive fails)
…
21:25:50.471Z [dave] Failed to decrypt a packet (14 consecutive fails)
21:26:42.813Z [stats] user=<гость> rtp=1824 seq_lost=4 dave_dropped=44 decoded=1780 … lost=2.6%
```

**Канал опустел.** Новая эпоха, сессия пересоздаётся, переход 0:

```
21:27:37.155Z [dave] Preparing for epoch (1)
21:27:37.160Z [dave] Session reinitialized for protocol version 1
21:27:37.174Z [dave] Transition executed (v1 -> v1, id: 0)
```

**Welcome на transition 0 (условие #11653).** Бот остался в опустевшем канале, кто-то вернулся. Ошибок одна-две, приём вернулся: следующий фрагмент владельца начался через 2 с и записан целиком (24,8 с):

```
21:31:48.097Z [dave] MLS welcome processed (transition id: 0)
21:31:50.137Z [dave] Failed to decrypt a packet (1 consecutive fails)
```

Порог 36 здесь не был достигнут, поэтому ветку, которую исправляет патч, прогон **не задел**. Патч остаётся страховкой на случай длинной серии ошибок.

**Сеть пропала у машины со шлюзом (~10 с).** `@discordjs/voice` восстановил соединение сам, без переподключения от watchdog. Потерянное видно только по `seq_lost`, и это 169 пакетов (~3,4 с):

```
21:26:40.032Z [voice] состояние ready → connecting
21:26:40.792Z [voice] состояние connecting → ready
21:27:15.841Z [stats] user=<владелец> rtp=6037 seq_lost=180 dave_dropped=6 decoded=6031 … lost=3.0%
```

Пропажу сети **у участника**, а не у шлюза, прогон не проверял.

## Эхо-тест

Критерий этапа 2 из `docs/PLAN.md`: в канале владелец, Прототип и 1–2 человека; 15 минут без пропадания приёма, со входами и выходами и ротацией ключей DAVE; потоки не путаются; WAV сохранены. Не прошёл — план (б) из ADR 0002.

### Подготовка

1. Бот приглашён на тестовый сервер, `.env` и `config/settings.local.toml` заполнены (`docs/discord-setup.md`). В whitelist — владелец и Прототип. **Хотя бы одного участника оставьте вне whitelist**: так проверяется, что гостя не пишут.
2. В `config/settings.local.toml` нет секций `[gateway]` и `[recording]`, или в них `echo = true` и `enabled = true`.
3. `cd gateway && npm ci && npm test` — все тесты зелёные. Проверьте, что патч на месте: `grep -c "lastTransitionId !== undefined" node_modules/@discordjs/voice/dist/index.mjs` выводит `1`.
4. Запустите с записью лога в файл:
   ```bash
   mkdir -p ../data && npm start 2>&1 | tee -i ../data/echo-test.log
   ```
   В логе должно появиться `команды /join и /leave зарегистрированы на сервере`. Флаг `-i` нужен, чтобы `tee` не завершился от Ctrl+C раньше шлюза и в лог попали финальные строки `[stats]`.
5. Всем участникам — наушники: иначе эхо Клона попадёт обратно в микрофон, и потоки будут казаться перепутанными.

### Сценарий (15 минут)

Засеките время начала. Отмечайте в заметках время каждого шага: потом их сверяют с логом.

| Мин. | Шаг | Что проверить |
|---|---|---|
| 0 | Участник не из whitelist вызывает `/join` | Эфемерный отказ, бот никуда не заходит |
| 0 | Владелец вызывает `/join`, **не находясь** в голосовом канале | Эфемерное «зайди в голосовой канал» |
| 1 | Владелец и Прототип заходят в канал. **Бот заходит к людям**: владелец вызывает `/join` | Бот в канале, ответ «Захожу…». Сразу после этого Прототип что-то говорит — его фраза звучит эхом через ~2 с. Это сценарий #11653 |
| 2–4 | По очереди короткие фразы: владелец, Прототип, гость | Каждая фраза звучит эхом через ~2 с голосом того, кто говорил |
| 4–5 | Двое говорят одновременно | Оба голоса звучат эхом, смешанные |
| 5 | Третий участник заходит в канал (ротация ключей DAVE) и сразу говорит | Его эхо есть без повторного `/join`. У остальных эхо тоже не пропало |
| 6–8 | Обычный разговор | Эхо не пропадает ни у кого дольше чем на несколько секунд |
| 8 | Один участник выходит и через минуту возвращается (ещё две ротации) | После возвращения его эхо есть, у остальных не пропало |
| 10 | Владелец вызывает `/leave`, затем снова `/join` (бот снова заходит к людям) | Бот выходит и заходит, эхо работает у всех |
| 11–14 | Разговор, хотя бы раз все говорят одновременно | Как выше |
| 14 | Все, кроме бота, выходят из канала | Бот выходит сам не позже чем через 30 с |
| 14 | Заход и `/join`, затем все выходят, и через 10 с один возвращается | Бот остаётся в канале. Затем `/leave` |
| 15 | В терминале Ctrl+C, **пока кто-то говорит** (снова `/join` перед этим) | Процесс завершается, в логе есть финальные строки `[stats]` |

### Чек-лист прохождения

- [ ] Ни у кого из говорящих приём не пропадал дольше чем на 10 с. Если watchdog вмешивался, в логе после `[recv] … watchdog: переподписка` кадры от участника снова идут.
- [ ] Сценарий «бот заходит к людям» (минуты 1 и 10) — эхо сразу у всех, в том числе у тех, кто был в канале до бота.
- [ ] Потоки не путаются: эхо каждой фразы звучит голосом сказавшего, в WAV участника слышен только он сам.
- [ ] В `data/recordings/<Сессия>/` для каждого участника из whitelist, который говорил, есть `<user_id>.wav` и `<user_id>.segments.jsonl`. Все WAV открываются в аудиоредакторе, включая записанный в момент Ctrl+C.
- [ ] Файлов гостя (его user ID) нет ни в одном каталоге Сессии.
- [ ] Автовыход сработал не позже чем через 30 с, а при возвращении участника бот остался.
- [ ] Лог сохранён в `data/echo-test.log` для разбора (задача 7.2): переходы `[dave]`, ошибки расшифровки, переподписки, строки `[stats]` по участникам.
