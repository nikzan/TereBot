# План разработки Клона

Решения из опроса (2026-10-14). Термины — [CONTEXT.md](../CONTEXT.md), архитектурные решения — [adr/](adr/), ссылки и версии — [REFERENCES.md](REFERENCES.md).

## Решения

### Окружение
- Клон работает **только** на MacBook Pro M1 Pro, 16 ГБ, без внешних API ([ADR 0001](adr/0001-runtime-local-training-remote.md)). Обучение — на отдельном кластере (RTX 5000 Ada, 64 ГБ VRAM).
- Клона запускают вручную на время Сессии, режим 24/7 не нужен. Пока Клон работает, Discord-клиент на Mac не открыт.
- Discord-шлюз на Node, ядро на Python, между ними локальный WebSocket ([ADR 0002](adr/0002-node-gateway-python-core.md)).
- Монорепо: `gateway/` (Node), `src/terebot/` (Python, uv), `config/`, `scripts/`, `data/` (в `.gitignore`, на кластер переносится через rsync). Зависимости для обучения — группа `train`, на кластере клонируется тот же репозиторий.
- Разработка идёт на закрытом тестовом сервере. Бот-токен лежит в `.env` (в `.gitignore`). На основной приватный сервер переходим только после MVP.

### Модели на старте
| Звено | Выбор | Примерный бюджет памяти |
|---|---|---|
| Распознавание | GigaAM-v3 через `onnx-asr`, вариант CTC на CPU (`gigaam-v3-e2e-ctc` — с пунктуацией) | ~1 ГБ |
| LLM | Qwen3.5-4B Q4 через llama.cpp (Metal), режим рассуждений выключен | ~3 ГБ |
| Голос | Qwen3-TTS-12Hz-1.7B-Base, bf16, MPS | ~5 ГБ |

На 9B переходим, только если замеры покажут запас памяти и приемлемую задержку.
Если Голос не укладывается в RTF < 1 или в память, пробуем по порядку: **Qwen3-TTS-0.6B → Chatterbox Multilingual → синтез фразы целиком без стриминга**. VoxCPM2 на 16 ГБ рядом с LLM не рассматриваем.

### Приоритеты и пороги
- Главный приоритет — узнаваемость Голоса. Задержка не критична, но её замеряем.
- Ориентир: **≤ 4 с** от конца Реплики Собеседника до первого звука Клона.
- Жёсткое условие: **RTF Голоса < 1** на M1 Pro.
- Замеры: задержка каждого этапа (VAD/turn, распознавание, LLM до первого токена, Голос до первого чанка), задержка от конца реплики до первого звука, пиковая RAM. Пишутся в Журнал Сессии, включаются отдельным тумблером.
- Транскрипты Сессий сохраняются на диск, у логирования есть ручной тумблер.

### Политика Диалога (MVP)
- Диалог начинается со Слова-вызова. Слово-вызов настраивается, по умолчанию «Теребот»; сверяем нечётко, потому что распознавание может написать его по-разному. Слово-вызов отличается от имени Прототипа («Терешкин», «Терем»).
- Собеседник — любой участник из whitelist, Прототип в том числе. Слушаем только Собеседника по Discord user ID, Реплики остальных пишем в контекст или журнал.
- Диалог заканчивается после ~20 с тишины Собеседника после ответа Клона.
- Если кто-то другой произносит Слово-вызов, Клон договаривает текущую фразу и переключается на нового Собеседника: последний вызвавший главнее.
- Перебивание: Клон замолкает при ≥ 1 с устойчивой речи Собеседника, речь остальных игнорирует.
- Политика Диалога — отдельный модуль без аудио, сети и моделей: на вход события, на выход решения. Её проверяют текстовыми сценариями, а все пороги задаются конфигом.
- `/join` и `/leave` доступны любому из whitelist. Клон выходит сам, когда канал пуст. При входе произносит короткое приветствие (оно же прогревает Голос).
- Дословное зачитывание текста голосом Прототипа **не** запрещаем.
- Память между Сессиями в MVP не храним: долгосрочная память только Паспорт.

### Личность
- `config/passport.md` — Паспорт, целиком идёт в system prompt.
- `config/fewshot.jsonl` — пары «реплика → ответ Прототипа», пишутся вручную.
- `config/lexicon.tsv` — как Прототип произносит англицизмы и ники (для Голоса).
- Сленг, мат, англицизмы и «эээ» сохраняем. Их основу внесём в Паспорт на этапе 5.
- RAG, LoRA на LLM и инструмент экспорта переписки — после MVP.

### Данные Голоса
- Основной источник: удалённые сессии, на которых каждый пишет **локально** в WAV 48 кГц / 24 бит, а Discord нужен только для связи. Цель — 30–60 мин свободного разговора, а не чтения.
- Запасной источник: раздельные потоки из Discord-шлюза.
- Транскрипты вычитываются вручную (кто — см. открытые вопросы).

### Оценка Голоса
- На каждом шаге обучения: похожесть спикера (ECAPA) против отложенных реальных записей, ориентир — похожесть «реальная ↔ реальная»; разборчивость через GigaAM.
- На ключевых версиях: Слепой тест на 3–5 друзьях. Успех — синтез угадывают не чаще ~60–65%.

## Этапы

Каждый этап считается готовым, когда выполнен его критерий.

1. **Подготовка.** Discord-приложение и бот-токен (создаёт владелец), тестовый сервер, `.env`, каркас монорепо. *Готово:* бот онлайн на тестовом сервере.
2. **Эхо-тест** — главный риск проекта, идёт первым. Node-шлюз проигрывает каждому участнику его поток через 2 с и пишет WAV по каждому user ID. *Готово:* в канале владелец, Прототип и 1–2 человека; 15 минут без пропадания приёма, со входами и выходами и ротацией ключей DAVE; потоки не путаются; WAV сохранены. Не прошёл → план (б) из ADR 0002.
3. **Голос на MPS.** Qwen3-TTS-1.7B-Base zero-shot на любом голосе на M1 Pro. Сравнение zero-shot 2–3 моделей. *Готово:* измерены RTF, время до первого чанка и пиковая RAM. Решение: остаёмся на модели или переходим к следующему запасному варианту.
4. **Сбор данных.** Записи с Прототипом, сегментация, транскрипция GigaAM, вычитка, манифест JSONL. *Готово:* 30–60 мин вычитанной речи, отложенный тестовый набор.
5. **Дообучение Голоса** на кластере официальным скриптом Qwen3-TTS (или скриптом выбранной запасной модели). *Готово:* похожесть перестала расти, разборчивость не падает, Слепой тест пройден.
6. **Python-ядро.** WebSocket-транспорт, VAD + Smart Turn, распознавание, LLM, Голос, Политика Диалога со сценарными тестами, Журнал Сессии с метриками. *Готово:* полный цикл «реплика → ответ голосом» в Discord.
7. **MVP.** 1-на-1 в голосовом канале со Словом-вызовом, `/join` / `/leave`, автовыходом и приветствием; Паспорт заполнен. *Готово:* задержка ≤ 4 с по Журналу Сессии, RTF < 1, Сессия держится стабильно. После этого — переход на основной сервер.

После MVP: групповой режим (несколько Собеседников и решение, когда вступать в разговор), экспорт переписки, RAG и память между Сессиями, LoRA на LLM, при необходимости RVC-полировка тембра.

## Открытые вопросы
- Кто вычитывает транскрипты: владелец, Прототип выборочно проверяет?
- Какой микрофон у Прототипа?
- Работает ли Qwen3-TTS на MPS вообще и с какой скоростью — ответит этап 3.
- Правильно ли GigaAM распознаёт «Теребот» — выяснится на этапе 6. Если нет: нечёткое сравнение или смена Слова-вызова.
