# Настройка Discord для Клона

Эти шаги выполняет владелец один раз. Нужен аккаунт Discord и браузер. Термины — [CONTEXT.md](../CONTEXT.md).

## 1. Приложение и токен

1. Откройте https://discord.com/developers/applications и нажмите **New Application**. Имя любое, например `TereBot`; это имя увидят участники сервера.
2. В меню слева откройте **Bot**.
   - Нажмите **Reset Token**, подтвердите и скопируйте токен. Discord покажет его только один раз; если потеряли — сбросьте снова.
   - **Public Bot** выключите: приглашать Клона сможет только владелец приложения.
   - В разделе **Privileged Gateway Intents** ничего не включайте. Клону нужны только `Guilds` и `GuildVoiceStates`, они не привилегированные; Message Content не нужен.
3. В корне репозитория создайте `.env` из образца и вставьте токен:
   ```bash
   cp .env.example .env
   ```
   В `.env` строка должна выглядеть так: `DISCORD_TOKEN=<токен без кавычек>`.
4. Проверьте, что `.env` не попадает в git: `git status` не должен его показывать.

Токен — пароль бота. Не вставляйте его в чаты, issues и коммиты. Если он утёк, сразу нажмите **Reset Token** и обновите `.env`.

## 2. Тестовый сервер и приглашение

1. В Discord нажмите **+** в списке серверов → **Create My Own** → **For me and my friends**. Это закрытый тестовый сервер; на основной сервер Клон переходит только после MVP (см. [PLAN.md](PLAN.md)).
2. В Developer Portal откройте **OAuth2** → **URL Generator**.
   - **Scopes:** `bot`, `applications.commands`.
   - **Bot Permissions:** `View Channels`, `Connect`, `Speak`.
3. Скопируйте сгенерированную ссылку внизу страницы, откройте её в браузере, выберите тестовый сервер и нажмите **Authorize**.
4. Проверка: бот появился в списке участников сервера (пока офлайн — шлюз ещё не запущен).

## 3. ID сервера и участников

ID нужны для файла настроек. Реальные ID пишите не в `config/settings.toml` (он в git, там плейсхолдеры), а в `config/settings.local.toml` — он в `.gitignore`:

```bash
cp config/settings.toml config/settings.local.toml
```

Если `config/settings.local.toml` есть, Клон читает только его, а `config/settings.toml` игнорирует. Шлюз пишет в лог, какой файл прочитан.

1. Включите режим разработчика: **User Settings** (шестерёнка) → **Advanced** → **Developer Mode**.
2. **Guild ID:** правый клик по иконке тестового сервера → **Copy Server ID**. Это значение `guild_id`.
3. **User ID:** правый клик по участнику (в списке участников или по аватару) → **Copy User ID**. Добавьте ID всех, кому Клон должен отвечать, в `whitelist`, включая себя и Прототипа.

ID записываются строками в кавычках: они длиннее, чем безопасно хранит число в JavaScript.

```toml
[discord]
guild_id = "123456789012345678"
whitelist = ["111111111111111111", "222222222222222222"]
```

## 4. Запуск

```bash
cd gateway && npm start
```

В логе должны появиться имя бота и название сервера, а в Discord бот станет онлайн. Если в логе предупреждение, что бота нет на сервере, проверьте строку «Настройки:» — читается ли `config/settings.local.toml`, — затем `guild_id` в нём, и повторите раздел 2.

## Сводка прав

| Что | Значение | Зачем |
|---|---|---|
| Scopes | `bot`, `applications.commands` | бот-аккаунт и slash-команды `/join`, `/leave` |
| Права бота | View Channels, Connect, Speak | видеть голосовые каналы, входить и говорить |
| Gateway intents | `Guilds`, `GuildVoiceStates` | список каналов и кто в каком голосовом канале |
| Privileged intents | не нужны | Клон не читает текст и не следит за присутствием |
