### Память системы в режиме с LLM

Занятая память по `vm_stat` (active + wired + сжатая) и swap — в начале прогона и пик за прогон. Swap в начале уже был 3–3,5 ГБ: macOS не освобождает его после предыдущих прогонов.

По правилу из design.md («если swap растёт, конфигурация считается не уложившейся в память») строго проходит только конфигурация 5, а она медленнее реального времени. Рост у конфигурации 4 (0,2 ГБ) — на уровне фона, у 3 и 2 — заметный.

### Откуда память у MLX

Весь пик MLX-конфигураций набирается при загрузке модели и подготовке голоса (кодирование референса и первый синтез): пик после подготовки равен итоговому. Синтез фраз его не увеличивает. Веса 1.7B 8-bit — 3,1 ГБ, 0.6B bf16 — 2,5 ГБ, а пик 7,0 и 6,5 ГБ. Значит, большая часть — промежуточные буферы, а не веса.

## Путь PyTorch → MLX (задача 5.3)

`Qwen/Qwen3-TTS-12Hz-1.7B-Base` сконвертирован штатным конвертером: `python -m mlx_audio.convert --hf-path Qwen/Qwen3-TTS-12Hz-1.7B-Base --mlx-path data/models/Qwen3-TTS-12Hz-1.7B-Base-mlx-bf16 --dtype bfloat16` (`mlx-audio` 0.5.9). Ошибок нет, 4,2 ГБ.

**Совпадает:** 5 первых фраз набора с сидом 0 на своей конвертации и на `mlx-community/Qwen3-TTS-12Hz-1.7B-Base-bf16` дают WAV, одинаковые байт в байт. Чекпоинт, дообученный на кластере в формате PyTorch, можно будет запускать на MLX. Квантизацию в 8-bit своей конвертации ещё нужно проверить тем же способом: `--quantize --q-bits 8`.

## Chatterbox (задача 5.2)

Как запасной вариант для матрицы не нужен: конфигурации Qwen на MLX прошли RTF < 1 с LLM. Набор фраз всё равно прогнан без LLM, чтобы проверить адаптер (задача 4.4). Chatterbox в 2,5 раза медленнее даже PyTorch-версии Qwen, драйвер MPS выделяет 16,8 ГБ, а числа он произносит неразборчиво. Если MLX не подойдёт, следующий шаг — Qwen 0.6B, а не Chatterbox.

## Наблюдения

- **Первый звук.** У MLX он почти не зависит от длины фразы (1,2–1,7 с), потому что `mlx-audio` отдаёт чанк по 2 с звука (`streaming_interval=2.0`, значение библиотеки). Короткая реплика приходит одним чанком после синтеза целиком. Уменьшение `--streaming-interval` — первый кандидат, чтобы сократить задержку.
- **Короткие реплики.** У них RTF хуже среднего (конфигурация 3: 0,83 у реплик до 5 слов против 0,52 у длинной фразы) из-за постоянных накладных расходов. В Диалоге таких реплик много.
- **Числа.** Цифрами синтез ошибается: «2024 году» → «2004 Гваду» (конфигурация 4), лишнее слово перед «19:30» (3), «48» → «сорок 8» (1). Chatterbox числа почти не произносит. Числа нужно передавать в Голос словами.
- **Сленг и англицизмы.** Высокий CER в этой категории в основном из-за распознавания: e2e-модель пишет «Discord», «Go voice», «Pls» латиницей. На слух это нужно проверить отдельно, CER здесь завышен.
- **Омографы.** CER ударения не видит (по категории 0 почти везде). Оценка — только на слух в задаче 6.1.
- **Похожесть.** У всех конфигураций 0,47–0,52 при опоре 0,64: zero-shot узнаваем лишь частично. По этой метрике конфигурации почти не отличаются; финальная оценка Голоса — на этапе 5.
- **Окружение.** `qwen-tts` 0.1.1 работает только с `transformers==4.57.3` (issue #237). `resemble-perth` (водяной знак Chatterbox) требует `setuptools<81`. onnx-asr на CoreML падает с GigaAM.

## Выбор

**Конфигурация 3 (1.7B-Base, MLX 8-bit)** — решение владельца 2026-10-15. Основная модель плана, RTF с LLM 0,67 / p90 0,82, запас до 1 есть даже на коротких репликах, лучшая оценка на слух. Конфигурация 2 (bf16) хуже и на слух (3 / 3 / 4), и по скорости (p90 1,02), и по памяти (8,4 ГБ). **Запас — конфигурация 4 (0.6B-Base, MLX bf16):** быстрее и легче, на слух 4 / 4 / 3.

**Условие памяти не выполнено:** 7,0 ГБ при бюджете Голоса ~5 ГБ, swap в прогоне с LLM вырос на 0,7 ГБ. Следующие шаги, до этапа 6:

1. Выяснить, можно ли параметрами `mlx`/`mlx-audio` (лимит кэша, освобождение буферов после подготовки голоса) снизить пик конфигурации 3 до бюджета.
2. Прогнать конфигурацию 3 с `--streaming-interval 0.5` и с LLM — сократить первый звук.
3. Если память не снижается — переходим на конфигурацию 4 по запасному плану.

## Как повторить

```bash
# Без LLM; <группа>: tts-qwen-torch для 1 и 5, tts-mlx для 2–4, tts-chatterbox для 6.
uv run --group <группа> python scripts/bench_voice.py --config <N>
# С LLM: сначала llama-server и один прогревочный запрос (команды печатает скрипт, если сервер не запущен).
uv run --group <группа> python scripts/bench_voice.py --config <N> --with-llm
# Метрики качества.
uv run --group eval python -m terebot.voice_eval data/bench/<каталог>
```
